# Delivery location at customer checkout

Delivery checkout offers an optional fixed GPS pin or a pasted HTTPS Google Maps, Apple Maps or Waze link. GPS is requested only after the customer presses the location button; there is no continuous tracking. Customers can cancel an outstanding request, review the point in their map application, replace it or remove it. Permission denial, timeout, unavailable GPS and insecure origins show a manual link fallback. Checkout waits while GPS is pending.

The written address is optional when a valid map location is provided. Without a map location, a complete written address remains required. Optional written fields are inside an expandable section. There is no reverse geocoding, automatic address inference or delivery-area validation from coordinates. The validated `delivery_address.location_url` travels through the existing public endpoint and shared order service into the existing JSON address snapshot. Migration `202610230004_delivery_location_address.sql` permits map-only delivery destinations and skips inserting incomplete street addresses into `customer_addresses`; it preserves the shared pricing, role and channel checks. The Central de Pedidos map button prefers that validated URL and falls back to the written address for older orders. Opt-in browser address storage includes map-only destinations; historical server-side address reuse is unchanged.

Validate with `node --test tests/delivery-location.test.mjs`, the live `tests/delivery-location-smoke.test.mjs` with local environment loaded, `npm run test:whatsapp`, `npm run lint` and `npm run build`. The live test confirms map URL persistence and invalid URL rejection and cleans only its own fixtures.

Manual acceptance: open the HTTPS customer link on a phone, select delivery, add items, continue to contact/payment details, allow location and review the map point. Submit without a written address and verify that Central de Pedidos opens the same point. Also check optional references, denial/cancellation, pasted map links and complete written-address checkout without GPS. Physical-device GPS acceptance remains manual. Plain HTTP LAN IP origins generally cannot request browser geolocation; use the HTTPS preview link for phone testing.
