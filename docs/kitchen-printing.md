# Automatic kitchen printing

> Superseded by block 4A: see [printing-architecture.md](printing-architecture.md) for the current queue, shared layouts, browser/file drivers, additional items, configuration, review rules and manual tests. The paragraphs below describe the retired queue for historical context only. Do not activate stale browser tabs or use the retired `/api/staff/kitchen-print` endpoint; it now returns 410. The current file processor is launched by `local:start` and works without a visible browser page.

Confirming a pending order creates one durable `kitchen_print_jobs` entry in the same transaction as the order status change. Newly opened staff orders also enqueue a ticket. No historical backfill occurs. The initial job is unique per order. Additional items added to an already-open order do not create an extra automatic job in this version; use manual printing when needed. The receipt loads the current complete order, quantities and observations.

In Settings → Impressão, administrators can enable/disable automatic queue processing. On the actual kitchen computer, open `/kitchen` with a kitchen/admin account and choose “Ativar neste computador”. This browser preference persists locally. Keep the page open and visible. The authenticated worker polls every five seconds, and a database lease permits one active automatic terminal at a time. Automatic jobs wait if no terminal is active. Do not enable multiple computers; another terminal can take over after an inactive lease expires.

The worker loads an isolated staff-only 80 mm receipt, records dispatch and calls the browser print dialog automatically. With no hardware, choose “Salvar como PDF”. This is browser-level automatic printing, not a silent operating-system spooler integration. Silent output requires configuring a dedicated printer/browser or implementing a local printer agent after selecting the hardware. No printer driver, kiosk setting or external print service has been installed.

“Enviada ao navegador” means the print attempt was dispatched; it does not verify paper output. Browsers cannot reliably distinguish completed printing from cancellation or paper failure. Uncertain/failed claims are never automatically resent. Stale reservations become manual-review errors after two minutes. The queue offers explicit manual reprinting; the existing Central de Pedidos print button remains, alongside an isolated kitchen-ticket button. Manual ticket dispatch prevents a still-pending automatic job from printing later, and is rejected while an automatic claim is active. A cancelled/closed order is skipped when an automatic terminal processes the pending queue.

Queue/lease tables are protected by RLS and narrow role-checked RPCs. Admin/kitchen can claim jobs; staff can explicitly request a manual ticket. Public customer endpoints cannot access printing, and the temporary customer gateway excludes print pages and staff print APIs. Changes in blocked staff roles apply to the RPCs through the existing active-role helper. Print errors do not undo order confirmation.
