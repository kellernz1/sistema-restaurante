# Delivery fees by road distance

Settings supports `fixed` and `distance` delivery modes. Fixed preserves `delivery_fee`. Distance mode requires the restaurant origin coordinates and charges `max(1, ceil(ceil(route_meters) / (step_km * 1000))) * step_fee`. For 2 km / R$ 6: 0–2,000 m costs R$ 6, 2,001–4,000 m R$ 12, and 4,001–6,000 m R$ 18. Prices remain editable; existing orders retain their original fee.

Administrators edit the origin in the separate “Localização do restaurante” section of Settings, visible in both fee modes. They can load a full or shortened Google Maps link, use GPS while at the restaurant, or enter coordinates manually, review the map point and save settings. `/api/staff/restaurant-location` resolves map links for active admins only; it does not save settings automatically and is blocked by the public preview gateway. Location changes invalidate previous distance quotes through the existing pricing snapshot check. `tests/restaurant-location-smoke.test.mjs` verifies admin-only access and direct-coordinate links; `RESTAURANT_SHORT_LINK_TEST` optionally exercises a real short link.

The browser requests `/api/public/delivery-quote` with a map location. The server extracts pin coordinates, or follows at most five HTTPS HEAD redirects from exact Google short-link hosts, validating every redirect. Links without a usable coordinate require GPS or another pin link; written-address geocoding is not implemented. No straight-line fallback is used. The route is the OSRM driving/fastest route, including one-way roads as modeled by its map data; it is not a motorcycle-specific profile. Points snapped more than 250 m from roads are rejected. The fee applies to the outbound trip, not the return.

Quotes expire after 15 minutes. Private service-role-only quote rows contain the destination URL, measured distance, fee and exact pricing/origin snapshot. They are cached and requests are globally limited to one uncached route per second through PostgreSQL. The browser cannot submit its own fee or distance. Shared PostgreSQL order creation checks quote destination, expiration and current settings under the existing settings lock, and snapshots the fee and measured distance into the order. Expired quote rows are removed on subsequent quote creation. Cashier orders use the same quote and pricing rules; uncertain retries retain the original request ID. The orders hub shows distance and the map point.

Migrations: `202610230005_distance_delivery_pricing.sql` and `202610230006_delivery_distance_snapshot.sql`. Database types have been regenerated. The public preview gateway now permits only the additional quote endpoint alongside its existing customer routes.

Routing configuration: `DELIVERY_ROUTING_URL` is a trusted server-only OSRM-compatible base URL (for example an own OSRM instance). In explicit `APP_MODE=local`, an absent value uses `https://router.project-osrm.org` only for non-commercial testing. The public OSRM demo is limited to reasonable non-commercial usage, at most one request per second, without availability guarantees; configure an own or appropriately licensed routing service before commercial operation. In other application modes the URL is required. No API key or paid subscription was installed. Route calculation requires connectivity to the configured service; existing fixed-fee local operation remains independent of it.

Validation: native pricing and map-parser tests, all eight SQL test files (transaction rollback), WhatsApp tests, lint and production build. `DELIVERY_ROUTE_SMOKE=true` with the normal local HTTP test environment runs `tests/distance-delivery-smoke.test.mjs` against the configured real routing service, checks cache reuse and final order totals, and cleans only its own fixtures. Other legacy HTTP smoke fixtures assume fixed delivery settings. Manual acceptance: configure the restaurant origin and band values, select delivery in `/order`, add dishes, send GPS or a supported pin link in checkout, verify route km/fee/total and finalize. Test expiration, settings changes, failed routing and the cashier flow. Phone visual/GPS acceptance remains manual.
