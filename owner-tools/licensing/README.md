# Owner-only license issuer and reference server

This directory is a separate Node.js tool, not a restaurant service. Copy it to
the owner's trusted machine; do not distribute it as part of the restaurant app.
It needs only Node built-ins, no npm packages or Supabase access. The restaurant
app's integration distribution explicitly excludes this directory.

Never create/copy a production private key in the repository, restaurant notebook,
app environment, browser, dump, support ticket or chat. The CLI refuses key/registry
paths inside the application checkout and refuses `APP_MODE=local`. When copied
outside the checkout it still requires storage outside the tool source directory.
Test suites generate unrelated ephemeral test keys; they cannot sign production
licenses. No production key is supplied or generated by this block.

## Keys and issuing

PowerShell examples on the **owner machine**, from the copied tool directory:

```powershell
node cli.mjs keygen --directory D:\LicenseVault\keys
node cli.mjs issue --key D:\LicenseVault\keys\private.pem --registry D:\LicenseVault\registry.json --installation INSTALLATION_UUID --restaurant "Pilot restaurant" --days 30 --grace 7 --plan pilot --request REQUEST_UUID --out D:\LicenseVault\pilot.license
node cli.mjs extend --key D:\LicenseVault\keys\private.pem --registry D:\LicenseVault\registry.json --installation INSTALLATION_UUID --days 30 --grace 7 --request ANOTHER_REQUEST_UUID --out D:\LicenseVault\pilot-renewed.license
node cli.mjs list --registry D:\LicenseVault\registry.json
```

Use real UUIDs. Copy the installation ID from restaurant Settings → License.
`issue` registers it once; use `extend` afterward. A repeated `--request` UUID
with identical arguments returns the original token without extending twice;
changing arguments under that UUID fails. Without `--request`, each `extend`
is a new explicit owner action. Keep the registry/issued history, not just keys.

Use `--out` to publish a nonempty UTF-8 license atomically, without printing its
contents or replacing an existing file. If emission fails, the command exits
nonzero with a sanitized message and does not create a license file. Never pipe
issuance directly into `Set-Content`: PowerShell may create an empty file even
when the native command failed. Replay the same request to a new output path if
publication failed after the registry committed; do not extend the subscription again.

```powershell
node cli.mjs issue --key D:\LicenseVault\keys\private.pem --registry D:\LicenseVault\registry.json --installation INSTALLATION_UUID --restaurant "Pilot restaurant" --days 30 --grace 7 --plan pilot --request REQUEST_UUID --out D:\LicenseVault\pilot.license
```

## Safe PowerShell test walkthrough

Run each command separately. Stop immediately at an error; do not paste the next
command into a `Read-Host` prompt. On the owner machine, copy this tool to an
external directory and keep the vault as its sibling (never inside the tool).
Use Node 22.18+ or 24 LTS. These commands do not print private keys, passwords,
tokens or environment values. Generated test keys must not replace production keys.

1. Set the repository location (no output expected):

   ```powershell
   $repo = 'C:\Users\Diogo\Desktop\sistema-restaurante'
   ```

2. Choose the external test workspace (no output expected):

   ```powershell
   $testRoot = Join-Path $HOME 'MesaCertaLicenseTest'
   ```

3. Create only the tool directory (no output expected):

   ```powershell
   New-Item -ItemType Directory -Path (Join-Path $testRoot 'tool') -Force | Out-Null
   ```

4. Copy the tool, including the corrected CLI (no output expected):

   ```powershell
   Copy-Item -Path (Join-Path $repo 'owner-tools\licensing\*') -Destination (Join-Path $testRoot 'tool') -Recurse -Force
   ```

5. Select the sibling vault (no output expected):

   ```powershell
   $vault = Join-Path $testRoot 'vault'
   ```

6. Remove only this terminal's restaurant mode flag (no output expected):

   ```powershell
   Remove-Item Env:APP_MODE -ErrorAction SilentlyContinue
   ```

7. **Only for a new test vault**, generate keys. Existing keys must be reused,
   not regenerated. Success prints only file paths; existing key files cause failure:

   ```powershell
   node (Join-Path $testRoot 'tool\cli.mjs') keygen --directory (Join-Path $vault 'keys')
   ```

   Confirm success before continuing:

   ```powershell
   if ($LASTEXITCODE -ne 0) { throw 'Key generation failed. Stop here; do not replace existing keys.' }
   ```

8. Obtain the installation UUID. At the prompt paste **only the UUID** copied
   from Settings / License, then press Enter; do not paste another command:

   ```powershell
   $installationId = (Read-Host 'Paste only the installation UUID').Trim()
   ```

9. Validate it without displaying its contents (no output means success):

   ```powershell
   if ($installationId -notmatch '^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[1-5][0-9a-fA-F]{3}-[89abAB][0-9a-fA-F]{3}-[0-9a-fA-F]{12}$') { throw 'Invalid installation UUID. Stop here.' }
   ```

10. Generate an idempotency identifier (no output expected; preserve it for retries):

    ```powershell
    $requestId = [guid]::NewGuid().ToString()
    ```

11. Issue a new installation's one-day test license with one-day grace. This is
    one physical command line; expect `License file created successfully.` only.
    An already registered installation requires `extend`, or the original request
    replay. An existing output file is refused and preserved:

    ```powershell
    node (Join-Path $testRoot 'tool\cli.mjs') issue --key (Join-Path $vault 'keys\private.pem') --registry (Join-Path $vault 'registry.json') --installation $installationId --restaurant 'Mesa Certa - TEST' --days 1 --grace 1 --plan pilot --request $requestId --out (Join-Path $vault 'test-one-day.license')
    ```

12. Check the exit status (no output means success):

    ```powershell
    if ($LASTEXITCODE -ne 0) { throw 'Issuance failed. Stop here; do not import any file.' }
    ```

13. Check existence/size without displaying the token (no output means success):

    ```powershell
    if (!(Test-Path -LiteralPath (Join-Path $vault 'test-one-day.license')) -or (Get-Item -LiteralPath (Join-Path $vault 'test-one-day.license')).Length -lt 20) { throw 'License file missing or empty. Stop here.' }
    ```

On the restaurant notebook, configure only `LICENSE_PUBLIC_KEY` using the
`public_key` field of `public.json`: exactly 64 hexadecimal characters, not a
Notepad command, path or JSON document. Do not display or share `.env.local`.
Save as UTF-8. Run the following individually, waiting for successful completion:

```powershell
npm.cmd run local:stop
```

```powershell
npm.cmd run local:update
```

```powershell
npm.cmd run local:start
```

Expect stop confirmation, successful build/update, then supervised services ready.
In Settings / License select `test-one-day.license` and click Import license;
no clipboard or token printing is needed. The one-day license shows expiring
(`A vencer` / `Por vencer`), with pilot features. Errors appear next to Import.
Do not import `private.pem` or `public.json`. A pinned public key cannot be changed
by simply editing the environment; owner maintenance is required.

`public.json` contains `algorithm` and the 64-hex-character Ed25519 `public_key`.
Send **only** that public value for the restaurant's `LICENSE_PUBLIC_KEY` setting.
`private.pem` is PKCS#8 private material. Restrict its OS permissions; `mode 0600`
alone is not a Windows ACL guarantee. Keep an encrypted offline backup and a
second protected copy of keys **and registry**, with recovery passwords stored
separately. Never put plaintext private keys in an ordinary synced shared folder.

Days extend paid-through from the later of now/previous paid-through. The token
itself is capped at 31 days from issue, even for a longer prepaid subscription.
Default grace is seven days (0–31 configurable). Pilot always enables delivery
and WhatsApp. Other plans support `--features delivery,whatsapp` or `--features
delivery`; an empty feature list can be supplied as the API array `[]`.

Registry writes use an exclusive lock and atomic temporary-file rename. A leftover
lock after an unclean stop requires owner inspection, not automatic stale-lock
deletion that could race another issuer. One local registry/file server is a
reference deployment, not a high-availability multi-process licensing platform.

## Reference server

```powershell
$env:LICENSE_ADMIN_TOKEN = "RANDOM_SECRET_OF_AT_LEAST_32_CHARACTERS"
node cli.mjs serve --key D:\LicenseVault\keys\private.pem --registry D:\LicenseVault\registry.json --port 8787
```

The reference binds only `127.0.0.1`. For actual deployment the owner must host it
behind authenticated administration, HTTPS, backups, monitoring and appropriate
rate limits. Hosting/billing are not implemented. Never send the administrative
bearer or private key to a restaurant. Administrative requests require
`Authorization: Bearer ...`; comparisons are constant-time. Request bodies are
bounded to 16 KiB. The file server is intended for low-volume reference/testing.

API (JSON, `Cache-Control: no-store`):

- `POST /v1/renew`: `{installation_id, nonce, license}` → `{license}`. The current
  owner's signed token authenticates this installation. An unknown ID/license or
  invalid signature fails. The response token includes signed `online_nonce` and
  issuance time. Replaying the same installation/nonce returns the same token.
  Renewal **never extends paid-through**; it only refreshes signed proof/features.
- `GET /admin/installations/:id`: plan, paid-through, features, suspension and issue
  count. It returns no private key.
- `POST /admin/installations/:id/extend`: `{request_id,days,grace?,restaurant?,plan?,features?}`
  → `{license}`. UUID replay is idempotent; changed payload fails.
- `POST /admin/installations/:id/suspend`: `{request_id,suspended:true|false}` →
  `{license}`. Future renewals also carry signed suspension. Suspension is still
  applied only at the restaurant's safe boundary, not midway through service.

Renewal is authenticated by an existing signed license, not installation UUID
alone. The initial license must be issued/imported manually. Old still-valid
signed proof can recover a lost response, but cannot increase the subscription.
Suspension/revocation cannot become immediate while a restaurant is offline;
the signed validity/grace limits and next safe boundary still govern.

Run `node --test tests/licensing.test.mjs` from the app checkout for issuer/server
contract tests. `npm run test:all` also exercises actual restaurant import/renewal,
RLS, restricted settlement/refund and backup/restore in a disposable full stack.
